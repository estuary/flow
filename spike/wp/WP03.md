# WP03: Helper image and shim

## Goal
A container image that, given the mounts in CONTRACTS, boots a connector
image as a libkrun guest with the devices, files, console wiring, vsock
mapping, and exit-code path the design needs. Tested with a busybox guest.

## Read
- PLAN.md: "Inputs established before the spike" (libkrun facts), "Helper
  launch", "Helper image".
- CONTRACTS.md: "Tap network", "Helper CLI", "Egress binaries" (you exec
  them; stub them until WP02 lands), "flow-init" (you inject it; stub until
  WP04 lands).
- libkrun 1.19.4 header: `curl -sL https://raw.githubusercontent.com/containers/libkrun/v1.19.4/include/libkrun.h`.
  Do not read libkrun's main branch; it is the incompatible 2.0 line.

## May touch
`spike/helper/**`, `spike/tasks/helper-*.sh`.

## Deliverables
1. `spike/helper/Dockerfile` producing `localhost/flow-sandbox-helper:spike`.
   Prefer a Fedora base if it packages libkrun 1.19.x and libkrunfw; else
   build libkrun v1.19.4 from source and take libkrunfw from Fedora. Record
   which in STATUS (this is a listed unknown). Include: nftables, e2fsprogs,
   iproute, socat, tcpdump, conntrack-tools, the shim, `flow-init` (from
   WP04; a placeholder until then), `flow-sandbox-egress` and
   `flow-sandbox-resolver` (from WP02; placeholders that exit 0 until then).
2. The shim, Rust, using the `krun-sys` bindings pinned to the 1.19 ABI (or
   `dlopen` if simpler). Sequence per PLAN "Helper image". Specifics:
   - Tap: create `tap0` persistent, address `192.0.2.1/30`, up, BEFORE
     libkrun. libkrun's own TUNSETIFF then attaches to it. Then exec the
     egress binary, then start the resolver (not for `egress: none`).
   - Disk: `O_TMPFILE` in `/scratch-backing`, `ftruncate` to `diskMib`,
     `mkfs.ext4` on `/proc/self/fd/N` with options that avoid lazy init (try
     `-E lazy_itable_init=0,lazy_journal_init=0 -O ^has_journal -m 0 -q -F`;
     record what you settle on). `krun_add_disk3(..., "/proc/self/fd/N",
     KRUN_DISK_FORMAT_RAW, false, false, KRUN_SYNC_RELAXED)`.
   - Root: `krun_add_virtiofs3(ctx, "/dev/root", "/rootfs", 0, true)`.
     Venv: `krun_add_virtiofs3(ctx, "venv", "/venv", shm, true)` with `shm`
     512 MiB when `--venv-dax`, else 0.
   - Files: `krun_fs_add_overlay_file(ctx, "/dev/root", "flow-init", ...)`,
     `"flow-connector-init"`, `"image-inspect.json"`, `".krun_config.json"`.
     Paths have no leading slash. The data pointer must stay valid for the
     VM's life: mmap the files and never unmap.
   - `.krun_config.json`: `{"Cmd": [...], "WorkingDir": ..., "Env": [...]}`
     from the image inspect's `Config.Env` plus `LOG_FORMAT`/`LOG_LEVEL`
     passed by the caller's environment. Resolve `Config.User` to numeric
     uid:gid via `/rootfs/etc/passwd` and `/rootfs/etc/group` (default 0:0).
     Resolve the KNOWN UNKNOWN: whether `krun_set_exec` argv or `Cmd` wins
     in 1.19's init when both exist. Try `Cmd` alone first; record.
   - `krun_add_net_tap(ctx, "tap0", mac, COMPAT_NET_FEATURES, 0)`.
   - `krun_add_vsock(ctx, 0)` then `krun_add_vsock_port2(ctx, 49092,
     "/sock/init.sock", true)`. The explicit zero is load-bearing: see PLAN.
   - `krun_disable_implicit_console` then
     `krun_add_virtio_console_default(ctx, devnull_fd, 1, 2)`.
   - `krun_init_log(2, WARN or DEBUG, NEVER, 0)`. libkrun's log lines must
     not begin with a space; verify and prefix if needed.
   - `--thp-disable`: `prctl(PR_SET_THP_DISABLE, 1)` before start.
   - `krun_set_vm_config`, then `krun_start_enter`.
3. `spike/helper/vsock-echo`: tiny static binary that listens on AF_VSOCK
   port 49092 and echoes. Injected as `/vsock-echo` for the smoke test.
4. `spike/tasks/helper-build.sh` and `spike/tasks/helper-smoke.sh`.

## Verification (`helper-smoke.sh`, run via sudo podman, then repeat via
`spike/tasks/fake-reactor.sh` once WP00 is in)
With `--mount type=image,source=docker.io/library/busybox,destination=/rootfs`
and the CONTRACTS mounts:
```
--no-flow-init --exec /vsock-echo      ; echo hi | socat - UNIX-CONNECT:.../init.sock  -> hi
--no-flow-init --exec /bin/sh -c 'exit 7'                      -> helper exit code 7
--no-flow-init --exec /bin/sh -c 'cat /proc/partitions; ls /sys/bus/virtio/devices'
                                                                -> vda present; fs, blk, net, vsock, console, balloon, rng
--no-flow-init --exec /bin/sh -c 'echo err >&2; echo out'      -> "err" on helper stderr, "out" too (workload stdout maps to fd 1? record where it lands)
```
Also confirm: `nft list ruleset` inside the helper shows the stub table;
`ip addr show tap0` shows `192.0.2.1/30`; killing the helper with SIGKILL
leaves `/scratch-backing` empty and `df` unchanged.

## Out of scope
flow-init's contents, the real ruleset, the runtime switch.
