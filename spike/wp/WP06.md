## Facts from WP05 that shape this package
- `flowctl preview` validates the catalog through the LEGACY `runtime` crate
  before runtime-next drives anything, so every switched-on preview starts
  two unsandboxed `fc_*` containers (Spec, Validate) before the sandboxed
  `fs_*` one (Open onward). Experiments 3 and 4 therefore prove the sandbox
  on the Open-and-documents path; Spec and Validate parity is trivially
  "same code". Say so in `report/exp3.md` and `exp4.md`, and list
  "sandboxing Spec/Validate" as a phase-2 open problem in the report.
- Drive every preview through `spike/tasks/fake-reactor.sh`. The helper's
  `init.sock` is root-owned and a non-root host user cannot connect; the
  fake reactor is root, as production's reactor is, and it is the faithful
  path anyway. `preview-stub.sh` shows the shape, including `TMPDIR` under
  `$SPIKE_REACTOR_DIR` for the legacy validation path's bind mounts.
- The launch line carries `--env=LOG_FORMAT=json --env=LOG_LEVEL=<level>`;
  the shim reads those from its own environment into the guest's
  `.krun_config.json`. They are load-bearing, not stub-only.
- `fake-reactor.sh` mounts `$REPO_DIR/target`, but under mise the build lands
  in `$CARGO_TARGET_DIR` (`~/cargo-target/flow`), so that mount is empty and
  `preview-stub.sh` copies binaries around to compensate. Fix the script to
  mount `$CARGO_TARGET_DIR` when set (housekeeping, one line), then drop
  the copy step.
- Experiment 3's materialization half is unwritten: `preview-stub.sh` covers
  the capture only. Add a `materialize-sqlite` spec to `spike/catalog/` with
  its database under `/tmp` (writable root) and extend the harness. Do it
  against the real helper, not the stub.

## Steps
1. Merge state: `spike/tasks/helper-build.sh` must produce a helper image
   containing WP04's flow-init and WP02's binaries. Build the workspace so
   `flow-connector-init` has `--vsock-port` and `flowctl` has the switch.
   `spike/tasks/env-check.sh` passes.
2. Experiment 1: from `fake-reactor.sh`, run `flowctl preview` on the
   source-hello-world spec with the switch on. Then inspect the running
   helper: `podman inspect` for `CapAdd`/devices, `grep CapEff
   /proc/<shim pid>/status`, and `ls /dev` inside it. Record the exact
   `podman run` line the runtime emitted (`tracing::debug!` prints it).
3. Experiment 2 (`exp2-boot.sh`): 20 launches of source-hello-world through
   the switch, warm caches. Timestamps: T0 host wall clock before `podman
   run`; the shim logs its start and its `krun_start_enter`; flow-init logs
   `/proc/uptime` at exec and at handoff (kernel boot time is the first
   uptime reading); the runtime logs when the readiness byte arrives. Report
   median and p95 of total, and the breakdown. Baseline: same 20 launches
   with the switch off, to the same byte.
4. Experiment 3 (`exp3-parity.sh`): preview the Go capture and the
   materialize-sqlite spec with the switch on and off. Diff the documents
   and the connector log lines (mask timestamps and container names). Both
   diffs empty.
5. Experiment 4: a derivation spec in `spike/catalog/` with a pandas
   dependency and a policy file with `"allowAll": true`. Preview produces
   documents. Then `--exec /bin/sh -c 'df /scratch; du -sh /scratch/*'`
   after a run (or have the derivation log it) to record the footprint.
