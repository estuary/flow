# WP02: Egress ruleset, resolver, and probes (no VM)

## Goal
Everything experiments 6, 7, and 8 claim about egress, proven on this host in
a pair of network namespaces with no libkrun involved. WP07 later reruns the
same probes from inside a real guest.

## Read
- PLAN.md: experiments 6, 7, 8 and the baseline denylist paragraph.
- CONTRACTS.md: "Tap network", "Egress binaries", "Policy JSON", "Probes and
  benchmarks".

## May touch
`spike/egress/**`, `spike/tasks/egress-*.sh`.

## Deliverables
1. `flow-sandbox-egress` (Rust, in `spike/egress/`): policy JSON in, complete
   nftables ruleset out, applied with `nft -f -`. Also `--print` to emit the
   ruleset without applying, which the report quotes.
2. `flow-sandbox-resolver` (Rust): UDP forwarder per CONTRACTS. Adding set
   elements by spawning `nft add element ...` is fine for the spike; note
   the per-query cost in STATUS.
3. `spike/egress/probes.py`: the probe suite per CONTRACTS, stdlib only,
   Python 3.12+. Probe sets: `public`, `none`, `ratelimit`, `declared`.
   Each probe takes its targets from argv (helper IP, uplink IP, gateway IP,
   a public name, a name known to resolve to RFC1918, the nginx address, a
   short-TTL name).
4. `spike/tasks/egress-netns-test.sh` (sudo): builds a `helper` netns with a
   veth to the host (host masquerades it out to the internet) and a `guest`
   netns joined to `helper` by a second veth pair standing in for the tap
   (`192.0.2.1` / `192.0.2.2`). Runs the two binaries in `helper`, then
   runs `probes.py` in `guest` for each probe set with a matching policy,
   and reports pass/fail. Tears everything down on exit, including on error.

## Ruleset shape (constraints, not a spec)
Table `inet flow_sandbox`, replaced wholesale on apply. Expect chains for
forward (policy drop), input from tap (only guest-ip -> helper-ip udp/53),
output to tap (only replies, via conntrack), and nat postrouting masquerade
on the uplink. Rules the probes will exercise, in the order that makes them
composable: anti-spoof (`iif tap ip saddr != guest drop`), established/
related accept, `meta nfproto ipv6 drop`, `meta l4proto != {tcp, udp} drop`
(kills ICMP), baseline set drop (include the helper's own subnets read from
its interfaces at apply time), tcp/25 drop, then the accepts: `allowAll`,
`ip daddr @resolved`, `ip daddr . tcp dport @declared` (concatenation set).
Rate limits sit in front of the accepts on `ct state new`: `limit rate over
N/minute drop` and `add @dests { ip daddr timeout 1m }` with `size M` so
the sixth distinct destination fails to add and falls through to drop.
`egress: none` is the same skeleton with no accepts and no resolver.
