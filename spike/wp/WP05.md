# WP05: runtime-next spike switch

## Goal
`flowctl preview` drives connectors through the helper using the real
runtime code: same readiness protocol, log decoder, codec, and transaction
driving. Only the launch line and the dial change, behind an env var.

## Read
- CONTRACTS.md: "runtime-next spike switch", "Helper CLI", "Paths and

- PLAN.md: "Helper launch" only.
- `crates/runtime-next/src/container.rs`: `start`, `Guard`,
  `find_connector_init_and_copy`, `inspect_image_and_copy`, the stderr

## Design
In `start`, when `FLOW_SANDBOX_SPIKE_POLICY` is set:
- Make `<reactor_dir>/<id>/{init,sock,scratch}` and an empty `venv/` unless
  `FLOW_SANDBOX_SPIKE_VENV_DIR` is given. `<id>` is the container name.
- Reuse the existing copy/inspect helpers to write `init/flow-connector-init`
  and `init/image-inspect.json` (mode 0644 on the JSON as today), and copy
  the policy file to `init/policy.json`; the helper gets
  `--policy /init/policy.json`.
- `<id>` is the (random, unique) container name. Never reuse a directory: a
  stale `sock/init.sock` makes the helper fail with EEXIST.
- Build the helper `podman run` exactly as PLAN "Helper launch", with
  `--memory` = `MEMORY_MIB + MEMORY_OVERHEAD_MIB`, labels as today, and the
  helper args from CONTRACTS. Append `FLOW_SANDBOX_SPIKE_HELPER_ARGS`.
- Same spawn, same stderr pump, same readiness wait.
- Skip `inspect_container_network`. Dial with
  `Endpoint::try_from("http://[::]:50051")?.connect_with_connector(service_fn(
  move |_| UnixStream::connect(sock_path)))`, keeping the keepalive settings.
- `runtime::Container { ip_addr: "192.0.2.2", network_ports: [], ... }`.
- `Guard` drop removes `<reactor_dir>/<id>` best-effort after the process
  exits (the socket file and init copies live there).
- When the variable is unset, the existing path must be unchanged. Diff the
  generated `docker run` args against `master` for one launch to prove it.

## Stub helper (so this package tests without libkrun)
`spike/stub-helper/`: image `localhost/flow-sandbox-stub:spike` built from
the reactor image plus `socat`. Its entrypoint accepts the helper CLI, ignores
the VM flags, and does:
```
mount --bind /init /rootfs/init   # stub runs with --cap-add SYS_ADMIN; fine, it is not the thing under test
socat UNIX-LISTEN:/sock/init.sock,fork TCP:127.0.0.1:49092 &
exec chroot /rootfs /init/flow-connector-init --image-inspect-json-path=/init/image-inspect.json --port 49092
```
Set `FLOW_SANDBOX_SPIKE_HELPER_IMAGE` to it and
`FLOW_SANDBOX_SPIKE_HELPER_ARGS` so the extra `--cap-add` is passed (or add a
stub-only env var; record it). Works for static Go connectors; that is all
this package needs.
