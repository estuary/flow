# WP04: flow-init

## Goal
The static guest init that does what podman does for a container today:
network, writable root, mounts, environment, user, exec.

## Read
- PLAN.md: "flow-init (guest, runs as root under libkrun's init)" and the
  libkrun-init bullets under "Inputs established before the spike".
- CONTRACTS.md: "flow-init", "Tap network".
- STATUS.md entry for WP03 (how to boot a guest with `--exec`).

## May touch
`spike/flow-init/**`, `spike/tasks/flow-init-*.sh`, and the one line in
`spike/helper/Dockerfile` that copies `flow-init` in.

## Design
Rust, target `x86_64-unknown-linux-musl`, statically linked, `libc`/`nix`
only. No shell, no `ip`, no `mount` binary assumed in the image (Go
connector images are distroless). Steps, in order:

1. eth0: `SIOCSIFADDR`, `SIOCSIFNETMASK`, `SIOCSIFFLAGS` (IFF_UP|IFF_RUNNING),
   default route via `SIOCADDRT` with an `rtentry` (RTF_UP|RTF_GATEWAY). Write
   `1` to `/proc/sys/net/ipv6/conf/{all,default}/disable_ipv6`.
2. Writable root: libkrun's init has mounted devtmpfs at `/dev`, which is the
   one writable place. `mkdir /dev/.flow`; mount tmpfs there with
   `size=<upper>m`; create `upper`, `work`, `root` under it; mount overlayfs
   at `root` with `lowerdir=/`; move `/dev`, `/proc`, `/sys` into it
   (`MS_MOVE`); `pivot_root`; lazily unmount the old root. If overlayfs over
   a virtiofs lower refuses, record the exact error in STATUS before trying
   workarounds. It is a listed risk in PLAN experiment 5.
3. `/etc/resolv.conf` with `nameserver <ns>`; `/etc/hosts` with localhost
   and the guest's own name. `mkdir -p /venv /scratch`. Mount virtiofs tag
   `venv` at `/venv` read-only (`dax` if asked). Mount `/dev/vda` ext4 at
   `/scratch` read-write.
4. `--as-root-exec CMD`: `/bin/sh -c CMD`, wait, continue regardless of exit.
5. `TMPDIR=/scratch`, `UV_CACHE_DIR=/scratch`; chdir to the cwd flow-init
   started in (libkrun's init applied `WorkingDir`); `setgroups(&[])`,
   `setgid`, `setuid` unless `--run-as-root`; `execve` ARGV with the current
   environment.

Failure anywhere: one line to stderr (no leading space), exit 125.

## Verification (`spike/tasks/flow-init-test.sh`, uses WP03's helper with the
derive-python image, which has a shell)
```
--exec /bin/sh -c 'cat /proc/net/route; cat /proc/mounts; id; cat /etc/resolv.conf;
                   touch /etc/x && echo etc-writable; touch /venv/x || echo venv-ro;
                   df /scratch; env | grep -E "TMPDIR|UV_CACHE_DIR|PATH"'
```
Assert: default route via `192.0.2.1`; `overlay / ` in mounts; `virtiofs
/venv ro`; `/dev/vda /scratch ext4 rw`; uid 65534 (nobody); resolv.conf as
written; `etc-writable`; `venv-ro`; env shows `/scratch` and the image's
`PATH`. Then `--run-as-root --exec /bin/sh -c 'id'` shows uid 0, and
`--exec /nonexistent` exits 127 through the helper.
