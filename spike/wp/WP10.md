## Steps
Experiment 11:
- `--exec sh -c 'dd if=/dev/zero of=/etc/fill bs=1M'` until it fails;
  confirm ENOSPC at the `upper-mib` cap and read the helper's
  `memory.current` before and after.
- Same against `/scratch` up to `disk-mib`; confirm host `MemAvailable`
  does not drop to match, only disk usage under the reactor dir does.
- `--exec sh -c 'echo x > /usr/spike && echo ok'`; afterwards mount the
  image on the host (`podman image mount`) and confirm `/usr/spike` is not
  there. `--exec sh -c 'touch /venv/x'` fails.
- After the helper exits: `<id>/scratch/` is empty and `df` for that
  filesystem is back to its pre-run value.

Experiment 12 (probes; the source read is WP11):
- Python in the guest: `socket(AF_VSOCK)` connect to CID 2, port 1234 ->
  connection refused/reset. Port 49092 from the guest also refused (it is a
  host-initiated mapping).
- Send the TSI proxy-create datagram WP11 documents to the TSI control port
  over an AF_VSOCK dgram socket; inside the helper, `ss -tunap` before and
  after shows no new socket; helper stderr shows libkrun's warning if any.
- `lsblk`, `ls /sys/bus/virtio/devices` and their `device` type files;
  compare against the expected list in PLAN.

Experiment 13:
- Start a preview of the materialize-sqlite spec, `kill -9` the shim
  mid-transaction. Confirm: the runtime reports the socket close and the
  container exit; `podman ps` shows no helper; no `tap0` or netns remains
  (`ip netns list`, `ls /run/netns`); `df` shows the scratch space
  returned; the runtime removed `<id>/`.
- Panic: `--run-as-root --exec sh -c 'sysctl -w vm.panic_on_oom=1; python3
  -c "a=[]; [a.append(bytearray(64<<20)) for _ in range(1000)]"'`. Time from
  the OOM to the helper's exit; confirm the exit is non-zero and record the
  code and the kernel's last console line (run with `--debug`).
