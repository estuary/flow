vsock port and the two shares", from libkrun 1.19.4's source, including
"none found" where that is the answer. Also a wire-format note WP10 needs.

  established before the spike".

## Files to read, in this order
- `src/libkrun/src/lib.rs`: how `vsock_config` Implicit vs Explicit turns
  into `TsiFlags`; confirm `krun_add_vsock(ctx, 0)` yields a muxer with TSI
  fully disabled and the port map still active.
- `src/devices/src/virtio/vsock/muxer.rs`, `muxer_thread.rs`, `unix.rs`,
  `proxy.rs`, `tsi_stream.rs`, `tsi_dgram.rs`, `timesync.rs`, `reaper.rs`:
  every path where guest-supplied data selects a host resource (port, path,
  sockaddr, family), what gates it, and what an unmapped port gets. Document
  the TSI proxy-create datagram format (port constant, struct layout) so
  WP10 can send one and prove it is ignored.
- `src/devices/src/virtio/fs/server.rs`, `device.rs`, `augment_fs.rs`,
  `read_only.rs`, `linux/passthrough.rs`: every ioctl the guest can issue
  (the exit-code ioctl 0x7602, the "remove root dir" request, anything
  else), what `read_only` actually blocks (does it cover ioctls, xattrs,
  fallocate, setattr?), and how lookups are confined to the shared
  directory. Answer the README's warning ("does not provide any protection
  against the guest attempting to access other directories in the same
  filesystem, or even other filesystems in the host") concretely: is that
  about symlinks, hard links, `..`, file handles, or mount crossings? Since
  WP04b the ROOT share is read-write (podman's per-container layer, served
  by a server running as uid 0 in the helper), and the reactor directory and
  podman's storage sit on the same host filesystem, so answer it as a
  write-escape question: can guest writes land outside the shared directory,
  and what confines them. The venv and deps shares are read-only.
- `src/devices/src/virtio/net/tap.rs`, `worker.rs`: confirm the tap backend
  only moves frames and parses nothing beyond the virtio-net header.
- `src/devices/src/virtio/console/`: what the guest can do to the console
  ports beyond read/write (resize, control messages).
- `src/devices/src/virtio/balloon/`: what the guest can make the host do
  (madvise ranges: are they validated against guest memory bounds?).
